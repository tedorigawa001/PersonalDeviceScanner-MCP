## 中

- [x] **Windowsで読めないフォルダーの扱いをCIで確認する**（2026-10-12 完了）
  - 読めないフォルダーがあっても検査を続けて `partial` を返すテストは、`chmod` で読み取りを禁止する方式です。
    Windows では `chmod` で読み取りを禁止できないため、Windows のCIではスキップされています（2026-10-12 の初回CIで確認）。
  - Windows 向けに、ACL（`icacls` の deny 指定）で読み取りを拒否するテストを追加する。
    後片付けで拒否設定を外し、一時フォルダーを削除できるようにする。
  - 同じ方法で一覧取得を拒否したジャンクションを作れば、旧ジャンクション（`My Music` 等）に相当するケースも確認できる。
  - 完了条件: Windows のCIジョブで、該当テストがスキップされずに成功する。
  - 結果: ACL の deny を付けても、GitHub の Windows ランナーでは `SeBackupPrivilege` と `SeRestorePrivilege` が有効なため、
    拒否が素通りされてスキップになった（一時ブランチでの診断で確認）。
    特権をすべて外し、Administrators を deny-only にした制限トークンでテストを実行するよう変更し、
    Windows（Python 3.11 / 3.14）で「読めないフォルダーでも `partial` で続行」と「旧ジャンクションで検査が止まらない」の
    両テストが実行・成功した。

- [x] **MCPのキャンセル時に実行中のエンジンを止める**（2026-10-12 完了）
  - 以前は、順番待ちの検査ならキャンセルで中止されましたが、実行中のエンジンはタイムアウトまで動き続けていました。
  - 対応: キャンセルを受けた補助タスクが停止の合図（`threading.Event`）を出し、`run_bounded` が約0.1秒ごとに確認して
    プロセスを kill する。フォルダーの事前確認中も中止する。エンジンが止まるまでロックを保持し、同時実行1件は維持。
  - 子孫プロセスも、下の「子プロセスをまとめて停止できるようにする」の対応でまとめて停止するようになった。

- [x] **子プロセスをまとめて停止できるようにする**（2026-10-12 完了）
  - 以前は、タイムアウト・出力超過・キャンセルのときに kill されるのは、直接起動したエンジンだけでした。
  - 対応: POSIX はエンジンを新しいプロセスグループで起動して `killpg`、Windows は Job Object に入れて `TerminateJobObject`。
    Job には「ハンドルを閉じたら全員終了」を設定し、この基盤が異常終了しても残らないようにした。
    エンジンの正常終了後に残ったプロセスや、Ctrl+C などの想定外の例外のときも停止する。
  - 限界: 自分から新しいセッションを始めたプロセス（POSIX）は止められない（出力を開いたままならエラー）。
    Windows では、起動から Job への割り当てまでの一瞬に作られた子プロセスは対象外。Job を作れない環境ではエンジン本体のみ停止。

- [x] **ClamAVの定義ファイルの鮮度を確認する**（2026-10-12 完了）
  - 以前は「定義の鮮度は未検証」という警告のみでした。
  - 対応: 検査の前に `clamscan --version` を実行し、`ClamAV <エンジン版>/<定義の版>/<作成日時>` を読む
    （形式は ClamAV 1.5.4 のソース `common/misc.c` の `print_version` で確認。日時はローカル時刻の ctime 形式）。
    `max_signature_age_days`（既定7日。ClamAV 自身の警告と同じ）より古い、または日付が分からない場合は、
    検査は行ったうえで `partial` と警告を返す。結果の `data.signatures` に版・作成日時・経過日数を入れる。
  - 実機で確認すること: 各OSの clamscan で `--version` の出力がこの形式であること（受入試験の項目に追加）。

- [x] **Wazuhの端末同一性を確認する**（2026-10-12 完了。鮮度は下の「要判断」へ）

- [x] **Wazuhで10000件を超える結果を取得できるようにする**（2026-10-12 完了）
  - 以前は `from`/`size` 方式の `offset` で、上限は9500でした。
  - 対応: `search_after` に切り替え、前ページ最後の記録の並べ替え値を `data.next_cursor`（base64url の JSON）として返す。
    AI や CLI はそれを `cursor` に渡す。カーソルは信用しない入力として、形・型・長さを検査する。
  - 並べ替えは深刻度のあと CVE と、Wazuh がパッケージを識別する5項目（syscollector の `PACKAGES_ITEM_ID_FIELDS`:
    名前・版・アーキテクチャ・形式・場所 → `package.name`/`version`/`architecture`/`type`/`path`）で、端末内で一意になる。
  - Point in Time は使わない（indexer アカウントの権限追加と indexer 側の状態保持が必要なため。権限を増やさない方針に合わせた）。
    そのため取得中に Wazuh が更新されると、ページ間で記録がずれることがある。
