# プロセスの起動元・ランタイム実体確認

2026-10-31：読み取り専用の第1段階を実装。実プロセスの識別情報は設計・試験記録に含めない。

## 目的

署名済みのNode.jsやPythonだけを見ても、実行スクリプトの目的は分からない。
親が終了してPID 1に引き取られても、起動設定との照合で由来を確認できる場合がある。
この機能は根拠と未確認事項を示し、感染・安全の判定や自動修復はしない。

## 第1段階の対象と公開境界

`review-processes [--json] [--show-details]` とMCPの `review_processes()` を追加する。
既定で無効。所有者が設定した最大16組のPID・開始時刻だけを対象にし、重複指定は拒否する。
AIからPID、パス、SQL、コマンド、設定上書きを指定できる入口は作らない。
接続観測のMCP識別情報提供許可とは独立し、接続先・ソケット情報を収集しない。

```toml
[process_review]
enabled = false
timeout_seconds = 15 # 1..60。コマンド・処理ループの期限

# 所有者が確認対象を登録。以下のPID・開始時刻は例であり、そのまま使わない。
# [process_review.targets.example]
# pid = 12345
# start_time = 1790000000 # osquery processes.start_time の整数（秒）
# script_file = "/absolute/local/script.js" # 任意。所有者が関連を指定したファイル
# package_file = "/absolute/local/package.json" # 任意。Node依存の配置確認
# launch_file = "/absolute/local/agent.plist" # 任意。macOS GUI LaunchAgentの照合
```

MCP応答はP01等の実行内ラベル、ランタイム分類、状態コード、注意点の件数・制約だけ。
設定した別名も返さない。CLIの既定も同じ匿名要約。`--show-details` の明示指定でだけ
ローカルに実名・PID・親のパス・所有者指定ファイルのパス・ハッシュ・パッケージ名を表示する。
MCPとCLI既定は許可項目で応答を作り直し、設定警告・所見はコピーしない。
エラーは識別情報を含まない固定文（無効・対象なし・実行中・設定不正・osquery未設定）だけを通し、
それ以外は汎用文に置き換える。CLI既定は省いた警告の件数だけを標準エラーに出す。
現行の第1段階では詳細はメモリー内で扱い、この操作を履歴保存・詳細保存・ダッシュボードの対象に登録しない。
他の検査の `history.details` を有効にしても、この機能の情報は保存しない。
CLIの出力を保存・AIに貼り付ける場合は、所有者が保存先の権限・提供範囲を判断する。

## 取得と照合

- osqueryの固定投影で対象プロセスのPID・開始時刻・実行パス・名前・親PID・親パス・親開始時刻だけを取得。
  SQLのPIDは設定検証済み整数。コマンドライン・環境変数・通信本文・プロセスメモリーは収集しない。
- 処理前後で開始時刻と実行パスを再確認。終了・PID再利用・不一致は関連付け不可として `partial`。
  最後の確認が失敗・中断した場合は、確認中だった対象の起動元の確定状態と詳細を残さない。
  最終確認を終えた対象は、その後に中断してもそのまま返す。
  秒単位の開始時刻・非原子的JOINの限界は常に示す。
- 実行ファイル名からNode/Python/その他を分類するだけで、署名や安全性を推測しない。
- 所有者指定のスクリプトは実行せず、最大1MiBのハッシュ・サイズ・全ユーザー書込可否だけを確認。
  コマンドラインを読まないため、そのファイルが実際にロードされた証明にはしない。
- 指定したpackage.jsonの直接依存は最大100件。標準の祖先node_modulesだけでメタデータを探索する。
  パッケージの名前一致を確かめるが、メタデータ発見はNodeの実解決・ロードの証拠ではない。
  先の候補がリンク・読取不可なら後の候補へ黙って進まず `resolution_unavailable`。
  未発見を未使用・悪性と呼ばない。NODE_PATH、PnP、グローバル配置、任意依存、ネイティブ処理、
  バージョン範囲・ロックとの照合、OSV照合は第1段階では行わない。
- 指定したplistのProgram/ProgramArgumentsを実行パス・所有者指定スクリプトと完全一致で照合。
  `launchctl print gui/<実行ユーザーUID>/<検証済みLabel>` の最上位の項目で、読込元（path）が指定plist、
  program が実行パスと一致し、引数に所有者指定スクリプトを含み、PIDも一致した場合だけ `loaded_job_pid_matches`。
  設定一致だけ、ラベルとPIDだけの一致、読み込み後に変更されたplistは未検証とする。
  RunAtLoad・KeepAliveは設定の有無として示す。
  Programの別名・シンボリックリンク経由の同一性は推測しない。親情報は観測で、元の起動者の証明とはしない。

## ファイルと停止の境界

POSIXでは各親ディレクトリをdescriptorで固定し、リンクを辿らず、クラウド未取得・FIFO・特殊ファイル・
ハードリンク・他者所有・1MiB超過を拒否する。入力ファイルの権限は変更しない。
依存パッケージのシンボリックリンク（pnpm等）も第1段階では拒否する。
Windowsではこのファイル読取バックエンドを未対応とし、項目ごとに未確認を返す。ハンドル方式での対応は後続。

osquery読取は既存の出力・累積量・2秒上限を再利用。launchctlは固定絶対パス・shellなし・最大128KiB・2秒。
キャンセルと期限をコマンド・ループ・ファイル読取の間で確認し、ロックを必ず解放する。
同一Scanner内は同時1件。MCP取消は既存のworker停止経路を使う。
ローカルファイルのstat/open/readそのものは、停止不能なネットワークファイルシステムでブロックしうる。
その場合の時間上限は保証しないことを制約として返す。権限昇格・インストール・自動起動解除・停止・遮断はしない。

## 検証と後続段階

合成プロセス・一時ファイルだけで、無効時の無収集、設定検証、PID再利用・終了・再確認失敗、
正規化済みCLI出力、MCPの匿名化・設定警告遮断、実SDKのツール呼出し・取消、ファイル拒否、
依存未発見・リンク、起動引数の完全一致・読み込まれたジョブの照合、中断時の印付け、
履歴非保存（一時の履歴ファイルで有効にし、ファイルも保存失敗の警告も生じないこと）を確認する。
実ホストの接続先やソースはテスト・リポジトリに含めない。

後続は、実機受入、OS別起動方式、ローカル詳細の安全な保存・ダッシュボード、スクリプトの静的解析、
追加の依存解決方式、署名・権限の根拠統合、同意したローカル観測間の差分。
段階ごとの未対応を匿名応答でも表示し、「異常なし」「安全」へ丸めない。

ローカル保存・専用ダッシュボードの次段階は[追加設計案](process-review-storage-design.md)を参照。
設定とCLIの明示指定による保存、権限・期限・選択削除、HTMLの複製管理を定める。これは未実装であり、
MCPは引き続き匿名要約だけとし、保存・詳細照会・削除のMCP入口を追加しない。
