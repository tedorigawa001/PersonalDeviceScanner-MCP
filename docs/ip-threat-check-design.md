# 接続先IPのローカル脅威リスト照合

状態：初期実装済み（2026-10-31）。合成データのCLI・匿名MCP・ダッシュボードと回帰を確認。
公開リストのHTTPS形式確認・オフライン再生に加え、このMacの通常CLIで本番取得・毎時制限・権限・日時／鮮度を受入。
失敗保全等は外部通信を禁止したコピーで補助確認。実接続・ブラウザー・他OSの受入は未確認。
[外向き通信観測](outbound-connections-design.md)の追加段階として、既存の固定osquery投影を利用する。
コマンド・MCPツール・設定は実装済み。後続の受入項目と、未対応のWindowsキャッシュ基盤は末尾を参照。

## 目的と判定の限界

このPCのOS可視ソケットに現れた接続先を、取得済みの公開脅威リストと端末内で照合する。
一致した場合は根拠・情報の日時・未確認事項を添えて警告する。接続先IPを外部サービスへ照会しない。
CLI・MCP・ダッシュボードで結果を確認できるようにし、実接続情報はローカルだけに保持する。

リストとの一致は、プロセスの感染、接続の悪意、実送信、通信開始方向の証明ではない。
共有基盤・IP再割当て・リストの誤りによる誤検知もありうる。不一致は安全を意味せず、
私有アドレス・VPN・通常のHTTPSであることも安全の根拠にしない。
通信本文・パケット・TLS鍵・DNS通信を取得せず、逆引き、接続先への接続試験、プロセス停止、通信遮断は行わない。

## 初期情報源

初期候補は **Spamhaus DROPのIPv4／IPv6リスト**とする。単一IPのC2リストではなく、
提供元が悪用ネットワークとして列挙するCIDRへの一致を示す。警告の説明も「公開脅威リストのネットワークに一致」とし、
「このIPはC2」「このプロセスはマルウェア」と読み替えない。ASNリストは扱わない。

固定取得先は以下の2つ。利用者・AIがURLやHTTPヘッダーを指定する入口は設けない。

- `https://www.spamhaus.org/drop/drop_v4.json`
- `https://www.spamhaus.org/drop/drop_v6.json`

公式[説明](https://www.spamhaus.org/blocklists/do-not-route-or-peer/)で対象・JSON形式・更新頻度・出典表示の条件を確認した。
利用時は[Fair Use Policy](https://www.spamhaus.org/blocklists/drop-fair-use-policy/)を参照し、
配布時にも出典・公開日付・著作権表示を保持する。データを製品に同梱・再配布する方式は採らない。
データ利用条件をソフトウェア依存のライセンスとしてSBOMへ混同せず、READMEのデータ出典として明記する。

出典表示と名称の扱いを分ける。説明ページは製品で使う場合に提供元の出典表示と、日付・著作権表示の保持を求める。
一方、利用条件の3.2は提供元の名称を宣伝・販促・その他の商用資料に使うことを禁じている。
そのため提供元の名称は、READMEのデータ出典欄と、照合結果に添える出典表示だけに使う。
機能名・見出し・コマンド・設定キー・npmやPyPIの説明／キーワード・リリースノート・告知投稿には使わず、
「公開脅威リストとの照合」等の一般的な表現にする（`--check-ip-threats`・`ip_threats` はこの方針に沿う）。

更新間隔は最低1時間、通常1日を想定する。実装前の公開データ受入で、現行の応答形式・メタデータ・
日付と著作権表示・利用条件を再確認し、条件を満たさなければ別形式に黙って切り替えず未対応とする。
Feodo Tracker等の単一IPリストは後続段階。提供範囲・鮮度・誤検知特性の異なるリストを最初から混合しない。

## 観測・照合とリスト更新の分離

| 初期実装の入口 | 実施すること | 実施しないこと |
|---|---|---|
| CLI `outbound-connections --check-ip-threats [--json]` | 固定時間の観測と端末内照合。ローカル画面だけに実プロセス・接続先・一致根拠を表示 | リスト更新、外部照会、遮断 |
| MCP `check_connection_destinations()` | 所有者設定の観測と端末内照合。匿名要約のみ返す | 任意IP入力、履歴照会、詳細保存、ネットワークアクセス |
| CLI `update-ip-threat-lists [--json]` | 固定HTTPS取得先から公開リストを取得・検証し、安全にキャッシュ更新 | 実接続の収集、IP照会、管理者認証 |
| ダッシュボード | 保存を許可した結果の匿名集計とローカル詳細を表示 | 外部リソース取得、IP照会リンク、自動再観測・更新 |

観測やMCPツールの呼出しで更新を暗黙実行しない。MCPに更新ツールを追加しない。
観測・照合は対象PCについて読み取り専用、MCP annotationsは`readOnlyHint=true`・`openWorldHint=false`。
ローカルCLIの更新だけが公開サイトへの通信とキャッシュ書込みを行う。

更新通信では、提供元やDNS／ネットワーク設備に更新元の公開IP・固定User-Agent・アクセス時刻等が見える。
「外部通信がない」とは説明しない。一方、観測した接続先・PID・名前・件数・警告・履歴・キャッシュパスは
リクエスト、URL、クエリ、ヘッダー、エラー報告へ組み込まない。接続先をDNSBLへ問い合わせる方式も採らない。

## 許可と設定

```toml
# 既存設定。観測自体の許可が別途必要。
[outbound_connections]
enabled = false
expose_identifiers_to_mcp = false
save_details = false

# 初期実装。既定では無効。
[ip_threats]
enabled = false
allow_updates = false
cache_directory = ""       # OS別の私有状態領域。history.fileから独立
max_age_hours = 48          # 整数1..168。提供元公開日時を基準にする
save_details = false
```

- 照合には`outbound_connections.enabled`と`ip_threats.enabled`の両方を要求する。
  無効時は収集前に固定文で拒否する。観測時間・読取上限は既存設定を維持し、MCP引数で変更させない。
- 更新には`allow_updates=true`と専用ローカルCLIの明示実行を要求する。更新は観測許可から継承しない。
  設定キーを厳格に検証し、未知キーの警告にも対応する。
- 新MCPツールは`expose_identifiers_to_mcp`が有効でも匿名のまま。既存の
  `observe_outbound_connections()`は従来の識別情報提供許可を維持し、新ツールの匿名性とは分離する。
  実情報をローカル限定にする運用では既存の識別情報提供も無効のままにする。
- 詳細保存には`history.enabled`・`history.details`・既存の`outbound_connections.save_details`に加えて
  `ip_threats.save_details=true`を要求する。過去の接続保存許可から新しい照合詳細の保存許可を継承しない。
  新MCPツールからは、設定が有効でも実情報を含む詳細を保存しない。
- 試験ではすべての履歴・キャッシュ先を専用一時領域に固定し、既定の個人領域の解決が呼ばれたら失敗させる。

## 公開リストの取得・検証・キャッシュ

既存のTLS検証・リダイレクト拒否・時間上限・キャンセル・通信回収の基盤を再利用する。
環境変数のプロキシや認証情報を自動継承せず、固定HTTPS GETだけを行う。TLS検証を無効化しない。
取得先の名前解決・通信は更新時だけで、照合中には呼ばない。

- 更新全体30秒、各取得は残り時間と最大15秒の小さい方まで。成功／失敗／取消のすべてで通信資源を回収する。
- 応答は各4MiB・5万ネットワークまで、累計8MiB。JSONの深さ・行数・文字列長・重複キー・数値も制限する。
  Content-Lengthだけに依存せず、実読取バイト数で制限する。圧縮は要求せず、未知のエンコードは拒否する。
- JSON Linesと最終メタデータの現行形式を確認して専用パーサーを固定する。
  CIDRはstrictに正規化し、ファミリー・ネットワーク境界・根拠IDの形式を検証する。
  IPv4-mapped IPv6や私有・特別用途のネットワークをリスト側に許容して公開宛先と誤認させない。
  必須メタデータがない、形式不正、過大、予想外に空、部分取得なら全世代を不採用とする。
- 生データ・提供元公開日時・取得日時・各SHA-256・出典・著作権表示を世代単位で保持する。
  初期実装では生データをbase64付きの単一JSONに保持し、検証済み投影は世代ごとにメモリー内で再構築する。
  取得時刻を提供元の公開時刻として扱わない。SHA-256は整合性確認であり、提供元の電子署名とは説明しない。
- IPv4とIPv6が両方検証できた世代だけを原子的に公開する。片方の失敗で異なる世代を結合しない。
  更新失敗・容量不足・キャンセルで使用中の正常キャッシュを壊さず、更新成功と報告しない。
- フォルダー0700・ファイル0600、所有者・通常ファイル・リンク／再解析ポイント拒否、親固定、
  別プロセスロック、原子的置換を適用する。管理しないファイルは削除しない。
  Windowsで安全な保存基盤を満たせない場合は更新・読込とも未対応にし、パスだけの検査へ退化させない。
- キャッシュは現行と直前の正常世代まで、合計32MiB。ロック競合は固定理由で失敗し、自動再試行ループを作らない。
  読取側は1世代を固定し、照合中の更新で結果を混合しない。
- 最低更新間隔1時間を別プロセス間でも強制する。直近試行日時が未来・不正なら外部通信を繰り返さず拒否する。
  429等で応答が返る場合も短時間の再試行を行わない。手動実行やMCPから間隔を解除する引数は設けない。

## 鮮度と結果状態

`checked_at`・`feed_published_at`・`feed_retrieved_at`・`expires_at`を別々に持つ。
IPv4／IPv6それぞれの公開日時で判定し、全体鮮度は古い側を使う。
`checked_at < expires_at`だけをfreshとし、期限ちょうどはstale。提供元時刻の未来値、欠落、
取得日時の矛盾はunverifiedにする。設定を緩めても未知の日時をfreshにはしない。

観測・照合全体のwall-clock時間上限は既存の観測窓+5秒に含め、期限超過・取消で新しい一致判定を続けない。
照合は観測終了時刻の鮮度で評価し、処理途中に期限を跨いだ情報をfreshとして確定しない。

| 接続ごとの状態 | 意味と警告 |
|---|---|
| `matched` | freshなリストのCIDRに一致。「公開脅威リストに一致」の警告。感染と断定しない |
| `not_listed` | freshな対象ファミリーのリストに一致なし。必ず「安全を証明しない」を併記 |
| `unverified` | 対象リストがstale／欠落／破損／未対応、又は照合未完了。照合範囲不完全としてpartial |
| `not_applicable` | 私有・ローカル・特別用途・分類不明等。公開脅威リストの対象外であり、安全とはしない |

古いキャッシュの一致は`unverified`に`historical_match=true`を添えることはできるが、
freshな警告と区別して「古い情報に一致、現在は未確認」と表示する。古い情報の不一致を`not_listed`へ昇格しない。
不正なキャッシュには一致／不一致を付けない。両ファミリーのうち片方の期限切れでも当該範囲は未確認とする。
保存した過去結果に対して、現在のリストを黙って当て直さない。

`matched`が存在するだけなら収集結果の`status`をerror/partialにはしない。
観測・必要な照合が完了したことと警告の有無を分離する。読取失敗・上限・stale・照合中断はpartial。
接続一覧が0件でもリスト未確認を隠さず、観測失敗を「一致0件」として正常終了しない。

## 正規化・二重計上防止・性能

既存のソケット正規化と接続キーを維持する。IPv4-mapped IPv6はIPv4へ正規化し、scope付きIPv6は
既存分類を維持する。私有・リンクローカル・未接続UDPの宛先欠落を公開宛先として照合しない。
未接続UDPは既存の`destination_unavailable`に残し、架空のIPを作らない。

同一観測内で公開宛先IPを正規化して1回だけ照合し、その結果を接続レコードへ参照付けする。
重複CIDRは除去し、重なったCIDRはすべて根拠として保持しつつ、警告のユニーク宛先数は1とする。
表示する最長一致CIDRを固定し、根拠の省略数も返す。CIDR境界は数値比較し、文字列の前方一致を使わない。

区別する数は、ユニーク宛先数・一致したユニーク宛先数・一致した統合接続レコード数・
確認可能な生成時刻付きプロセス数・帰属未確認レコード数。サンプル回数を警告数や送信回数へ加算しない。
PIDだけでプロセスを結合せず、帰属未確認の接続を既知プロセスの警告と断定しない。
実行間のラベルや集計を合算せず、最新の観測1回を表示する。

5万CIDR×2000接続の総当たりを避け、検証済みリストからファミリー／prefix別の有界な索引を構築する。
各IPは最大33／129のprefix照合、頻繁な期限・キャンセル検査を行い、根拠数と結果サイズに上限を設ける。
警告を加えた結果も既存のローカル2MiB・MCP64KiBの上限を超えないよう計上する。
省略時は件数と理由を残し、非表示の一致を「一致なし」と誤読させない。

## CLI・MCP・履歴・ダッシュボード

CLIは情報源・公開／取得／照合日時・鮮度・期限と、接続ごとの状態を表示する。
照合結果を示すすべての場所（CLI、MCPの匿名要約、履歴の匿名集計、ダッシュボード）に、使ったリストの出典表示・
公開日付・提供元の著作権表示を添える。これらはリストのメタデータから取り、固定文で補ったり書き換えたりしない。
メタデータに著作権表示や日付がない世代は、上記の検証どおり採用しない。
一致した場合だけ、観測済みのプロセス名・PID／開始時刻・接続先・port・プロトコル・一致CIDR・根拠IDを
ローカル表示する。帰属が未確認なら明記する。不一致・未確認も別集計で表示する。
新しい警告は`findings=[]`を維持した専用の`destination_threats`領域に置き、
ClamAV感染件数・Wazuh脆弱性件数・一般ダッシュボードの深刻度円グラフへ加算しない。
CLI終了値は既存の0=処理完了／2=不完全・失敗を維持し、リスト一致をClamAVの感染終了値1へ流用しない。

MCPは同じ観測・照合結果から専用allowlistで匿名投影する。
実名・PID・開始時刻・実IP／port・scope・CIDR・一致根拠ID・ホスト名・パス・ファイルハッシュは返さない。
同一実行内だけの`P01`等と警告ラベル、状態・件数、情報源・リストの日時・鮮度・未確認理由を返す。
共有公開CIDRや根拠IDから接続先を推測できるため、これらも匿名応答から除く。
エラー・進捗・省略通知にも識別情報を含めず、例外原文・osqueryの生出力を返さない。
時間切れ・キャンセルでも同じ投影を使い、処理途中の実情報を漏らさない。

通常履歴は匿名の専用集計・日時・鮮度・制約だけを許可項目で保存し、読込時も再検証する。
ローカル詳細の保存は上記の別許可に従い、既存の私有履歴・保持／ローテーション方針を利用する。
MCPの匿名応答だけから実IP付き履歴を作らず、MCPの結果に詳細ファイル名やHTMLパスも含めない。

ダッシュボードは接続観測専用欄に、観測時刻・照合時刻・リスト公開時刻・期限・警告／未確認／対象外の件数を表示する。
「観測時点の照合結果」であり現在の安全判定ではないと明記する。保存時freshでも静的HTMLを開いた現在のfreshとは言わない。
詳細保存なしでも匿名集計を表示し、詳細がない理由を示す。詳細許可時だけプロセス別の接続先・根拠を開閉できる。
プロセス名・CIDR・出典文字列をHTMLとして解釈せず、整形改行と入力の制御文字を区別してエスケープする。
外部画像・スクリプト・CSS・解析タグを使わず、接続先IPを埋め込んだ調査リンクは設けない。
最新が空・partial・破損でも古い正常結果に置き換えず、同じ履歴の再読込で件数を増やさない。

## 回帰・受入の完了条件

1. IPv4／IPv6、CIDR先頭／末尾・範囲外、重複／重複範囲、mapped IPv6、scope、特別用途の正規化。
2. 同一IPの複数プロセス・port・サンプル、PID再利用、帰属未確認で宛先／接続／プロセスの数を二重計上しない。
3. 公開時刻基準の期限直前・ちょうど・1マイクロ秒超過、未来／欠落日付、取得したばかりの古いリスト、
   一方のファミリーだけ古い場合、期限を跨ぐ観測、historical matchの区別。
4. 不一致・私有IP・0件を安全と表示しない。キャッシュ欠落／破損／リスト更新失敗を正常な不一致にしない。
5. 更新先固定、TLS検証・リダイレクト拒否、サイズ／件数／JSON上限、毎時制限、429、
   更新中断と旧正常世代の保全、IPv4／IPv6の原子的公開、ロック競合・解放、所有者・リンク・権限・容量。
6. ヘッダー前／本文途中の低速応答で時間上限・キャンセル後に通信資源とロックを回収し、遅延更新を起こさない。
7. 観測・照合ではネットワーク関数を呼んだら失敗させ、更新要求には合成接続先やプロセス識別情報が一切入らないことを検証する。
8. 実MCP SDK stdioで成功・失敗・省略・取消・保存設定有効時の匿名／非保存を確認する。
   既存ツールの識別情報提供許可が新ツールを非匿名にしないことも確認する。
9. CLI・履歴・ダッシュボードの再読込、HTMLエスケープ・JSON整形・ページ内リンク、
   匿名集計と許可済み詳細の分離、一般の脆弱性円グラフに加算しないことを検証する。
10. Android・MCP関連を含む全テスト、npmの導入・MCP通し試験、対象OSのCIと安全な保存基盤の受入。
11. 実データ取得の受入は公式公開リストだけを取得して、検証結果・日時・件数・ハッシュを記録する。
    CIDR境界の照合はメモリー内の数値だけで行い、登録先には接続しない。実接続の収集は別の明示的な受入とする。
12. 最初のブラウザー受入は合成データのみ。実情報の受入を行う場合も私有ローカル領域だけに保持し、
    リポジトリには匿名の結果・件数・対象コードのハッシュ・未確認事項だけを残す。
13. CLI・MCP・履歴・ダッシュボードの各出力に、使ったリストの出典表示・公開日付・著作権表示がメタデータどおりに付く。
    それらを欠く世代は採用しない。パッケージの説明・キーワード（`pyproject.toml`・ルートの`package.json`）と
    機能名・コマンド・設定キーに提供元の名称が入っていないことも確認する。

実装時にはREADME（両言語）・設定例・MCP説明・履歴スキーマを更新する。
新しいライブラリが必要なら全プロファイルのロック・SBOM・第三者表示まで整合させる。
設計作成時には実リスト取得・実接続収集・コード変更・テスト実行は行っていなかった。

## 初期実装と残る受入

`pc_scanner/ip_threats.py`にパーサー・単一世代キャッシュ・毎時試行制限付き更新・オフライン索引照合・匿名投影を追加。
既存の`process_store.Store`のdescriptor保護を再利用し、単一の原子的キャッシュを読む際はファイルロックを作らない
`file_lock=False`を使用する。更新は従来どおりファイルロックを取得し、所有者・権限・ローカルFSの制約を緩めない。
既定保存先の親がない場合は`cache_parent_missing`で拒否する。親を勝手に作成せず、READMEで設定方法を案内する。
公開時刻が旧正常世代より後退する応答は採用しない。公開日時が古いままの正常取得はfreshとして扱わない。
ローカル結果の根拠は宛先ごとに最長一致順で最大4件、超過件数を保持する。MCPは最大100匿名グループと省略件数を返す。

検証は[実装・検証記録](acceptance/ip-threat-check-2026-10-31.json)に保存する。
公開データの形式確認では固定HTTPS取得先にだけアクセスし、掲載されたネットワークの先頭・末尾アドレスは
数値として照合しただけで、そこへ接続していない。取得済みの実リストを更新処理へ再生した試験は
ダウンロード部分を置き換えたオフライン試験であり、本番更新の実機受入とは区別する。

通常の更新CLIによる実取得と別Pythonでの直後の毎時制限を
[macOS更新CLI受入記録](acceptance/ip-threat-update-macos-2026-10-31.json)に記録。
48時間の鮮度・0700/0600・旧世代バックアップと、コピー上での9件の失敗／境界試験を確認した。
境界時計はPython内だけを制御し、ダウンロードは再生またはDNS前に拒否した。OS時計の変更や実取得の毎時制限回避は行っていない。

残りは所有者が許可した実接続でのローカル照合、合成ページのブラウザー操作、
Linuxの新キャッシュ機能の受入・新CI、Windowsの安全な保存基盤である。既存のWindows/Linux受入結果を流用して完了にしない。
