# プロセス確認のローカル詳細保存・ダッシュボード表示

状態：初期実装済み（2026-10-31）。macOSの合成データと既存2プロセスで保存・管理・MCP非保存を部分受入。
実ブラウザー操作、Linux実機・新CIは未確認。Windows保存は未対応。
[第1段階](process-review-design.md)の収集範囲と匿名MCP応答を維持し、所有者がローカルCLIで保存・閲覧する。
通常履歴への保存は追加しない。[検証記録](acceptance/process-review-storage-2026-10-31.json)を参照。
[macOS受入記録](acceptance/process-review-storage-macos-2026-10-31.json)では、実osqueryの親開始時刻`-1`を
保存時に未取得の`null`に正規化し、確認済みの時刻として扱わない修正も検証した。

## 目的と対象外

起動元、ランタイム分類、所有者指定ファイルのハッシュ、依存配置、未確認理由を、確認時刻付きで端末内に残す。
保存できたことと確認できたことを分け、`partial` を「問題なし」に置き換えない。
対象スクリプトの起動・再実行、ソース本文・コマンドライン・環境変数・通信本文・接続先の収集は追加しない。
署名照合、依存の実ロード証明、外部照会、差分監視、プロセス停止・起動設定解除も本案の対象外。
依存確認は現行の標準祖先配置の範囲を引き継ぎ、NODE_PATH・PnP・pnpm等の追加解決は未対応として表示する。

## 許可と入口

保存には、所有者の設定 `process_review.storage.enabled=true` と、その実行のCLI引数
`review-processes --save-details` の**両方**を要求する。`--show-details` は表示許可であり保存許可にはしない。
`history.enabled` / `history.details` / 接続観測の詳細保存設定から許可を継承しない。
保存は通常の履歴から独立するため、`history.enabled=false` でも上記の明示許可があれば保存する。
この違いをREADME・CLIヘルプに明記する。どちらかの許可がなければ保存先を作らない。
`--save-details` が設定で拒否される場合は収集前に固定文で拒否する。

MCPの `review_processes()` は引数なし・匿名要約のまま。保存設定を有効にしてもMCP呼出しからは保存しない。
保存・過去結果の照会・HTML生成・削除・任意パス指定のMCPツールは追加しない。
MCPは保存ID・保存先・名前・PID・起動設定ラベル・パッケージ名・ハッシュ・HTMLリンクも返さない。
`get_scan_progress` は現行の匿名進捗だけを扱う。保存済みデータをプロセス確認の入力に逆流させない。

```toml
# 保存には enabled=true に加えて、CLIの --save-details が必要。
[process_review.storage]
enabled = false
directory = ""       # 空欄はOSの既定ユーザー状態領域内の専用フォルダー
retention_days = 7    # 整数1..30
max_records = 32      # 整数1..100
max_total_mb = 32     # 整数1..128。JSON・HTML・管理ファイルの合計
```

初期実装は、既存の安全なファイル読取を利用できるPOSIX環境を対象とする。
Windowsの保存は、ハンドル・所有者・実効ACL・再解析ポイント拒否の実装と受入が終わるまで拒否する。
OSに依存する未対応項目を、保存できたという理由で対応済みにしない。
Windowsへ対応するときは、削除前のファイル同一性確認にチェックポイントの `identity()` を再利用する。
Windows版Python 3.12以降は `os.stat` と `os.fstat` で `st_ctime` の意味が異なり、
これを比べた同一性確認がCIで失敗したため（2026-10-31）、新しく別の確認を作らない。

## ローカルCLI

| コマンド | 動作と公開範囲 |
|---|---|
| `review-processes --save-details [--json]` | 設定が許可したときだけ今回の結果を保存。標準出力は既定の匿名要約と不透明な保存ID・保存状態のみ |
| `review-processes --save-details --show-details` | 保存に加えて今回の実名・パスをローカルに表示 |
| `process-review-records list [--json] [--show-details]` | 既定はID・記録日時・状態・件数・期限・revision。実名・パスは明示表示だけ |
| `process-review-records dashboard [--no-open]` | 専用の私有HTMLを生成。実情報のローカル表示を許可する操作としてヘルプに明記 |
| `process-review-records delete ID --revision TOKEN` | 一覧で選んだ1件を再確認して削除。期限前のデータも所有者が選択できる |
| `process-review-records prune --expired [--dry-run]` | 期限切れの管理対象と、安全に検証した孤立一時ファイルを清掃。dry-runは記録削除をせず、不整合なHTMLの無効化は行う |

管理CLIは保存設定を無効に戻した後も、所有者の明示操作で既存データを一覧・削除できる。
無効化自体は既存データを削除しない。保存先がなければ一覧・削除・生成で作成しない。
通常の `dashboard` はこの保存領域を自動で読み込まない。初期実装は既存CSS・表示部品を再利用する専用ページとする。
通常履歴との統合は、別の明示許可を設計するまで行わない。

## 保存データと確認状態

ファイル名はOSの名前・PID・パス・時刻から作らず、暗号学的乱数の32桁小文字hex IDとする。
スキーマの版、保存ID、実行ID、収集開始・終了UTC、保存UTC、固定の期限、結果状態、制約、対象の配列を持つ。
実行IDは、収集を1回始めるごとに暗号学的乱数で作る不透明なIDで、その実行の結果と一緒にだけ保存する。
MCP・CLI既定の出力には出さず、設定・PID・時刻からは作らない。
収集開始・終了は保存処理側の既知の時計から記録し、保存日時を確認日時の代わりに使わない。
表示用ラベルは実行内のP01等。設定別名は不要なため保存しない。

保存項目は許可リストで構築する。対象ごとの確認状態と、現行収集器が返した確定前後照合済みの詳細に限る。
具体的にはPID・開始時刻・名前・実行パス・観測した親、所有者指定のファイルパス・ハッシュ・サイズ・権限の注意、
直接依存の名前・配置状態・メタデータの場所、起動設定のラベル・照合状態・設定フラグを含む。
ソース、package.json全文、起動設定の引数全文、OSコマンドの生出力、設定全文、エラー／警告の原文は保存しない。
エラーは固定コードと匿名の固定説明に限定する。既知のOS出力も信頼できないデータとして扱う。

保存単位は1実行。PIDだけ・同じ名前だけで別実行を結合しない。
収集と保存は1回のCLI呼出しの中で行い、1回の収集につき保存を試みるのは1度だけで、自動の再試行はしない。
`save_failed` の後に残したい場合は、所有者が収集からやり直す（新しい実行IDになる）。
したがって同じ実行IDの記録は1件だけのはずで、読み込み時に複数見つかった場合は整合しない記録として扱い、
件数に二重計上せず、どちらも最新の確定結果として表示しない。プロセスの継続実行やハッシュ一致を安全性の根拠にしない。

| 収集結果 | 保存の扱い |
|---|---|
| 正常完了 | 許可があれば保存 |
| 未発見依存・未対応などによる `partial`、`stop_reason=null` | 状態と制約を保持して保存。未確認を省略しない |
| 時間切れ・取消 | 自動保存しない。回収・ロック解放を優先し、保存状態は `not_saved_interrupted` |
| 読取上限・エンジン警告による停止（`stop_reason` がそれ以外） | 中断ではないが途中までの結果なので保存しない。保存状態は `not_saved_incomplete` |
| `error`・結果スキーマ不正 | 詳細保存しない。固定の失敗説明のみCLIへ返す |

時間切れ・取消で既に確認済みの対象がメモリー内に残っていても、停止後に背景保存を始めない。
収集完了後の保存中に取消が来た場合は、公開前なら一時ファイルを破棄する。
原子的な公開が先に終わっていれば `details_saved` として扱い、未保存と誤報しない。
保存失敗は収集結果の `completed` / `partial` と分離し、`save_failed` と匿名の固定警告を返す。
容量上限などで保存できないとき、以前の結果を新しい結果に見せたり、収集成功を保存成功と扱ったりしない。

## 保存先・権限・原子的な更新

既定の場所は `history.default_file()` が示すOS別ユーザー状態領域の親にある専用 `process-review` フォルダー。
所有者設定の `history.file` には追従しない。`history.file` の隣に置くチェックポイントとは意図して異なる。
一般履歴の保存先は要約のために選ばれた場所（同期・バックアップ対象を含みうる）であり、
より機微な詳細が設定の変更に黙ってついて行かないよう、別の保存先は `directory` で明示させる。
リポジトリ・作業ディレクトリ・一時フォルダーへ自動保存しない。

試験では、既存の `history.file` を一時フォルダーに向ける方法ではこの保存先を逸らせない。
保存を有効にする試験は必ず `directory` を一時フォルダーに設定する。加えて、試験中に既定の保存先が解決されたら
失敗させる。保存の失敗は `save_failed` の警告に変わり、例外を上げるだけの差し替えでは見逃されるため、
警告がないことと既定の保存先が作られていないことも確かめる（2026-10-31に一般履歴の非保存の試験で同じ見逃しがあった）。
明示した `directory` は絶対パス・親参照なしで、親が存在するローカル領域だけを認め、ユーザーの別名を勝手にresolveしない。
保存時に作成してよいのは検証済みの親直下の専用フォルダーだけとし、任意の祖先を再帰作成しない。
クラウド同期先・共有／ネットワーク保存先は対象外。既知の同期領域・未取得属性は拒否するが、全製品の同期設定の検出は保証しない。
設定画面・ヘルプで、同期しない所有者専用領域を指定する責任と検出限界を説明する。
ファイルを読む前の属性確認で未取得ファイルを拒否し、確認のためにダウンロードしない。

| 対象 | POSIX要件 |
|---|---|
| 保存フォルダー・配下の管理ディレクトリ | 実行ユーザー所有、0700 |
| JSON・生成HTML・ロック・一時ファイル | 実行ユーザー所有、0600、通常ファイル、リンク数1 |
| 祖先 | リンクを辿らず固定。別ユーザーが書き換え可能な経路を拒否。専用領域外の権限は変更しない |

既存の所有者不一致・広い権限は、黙ってchmodして取り込まず固定のエラーで拒否する。
既存の安全な原子的書込部品を、**親フォルダーの検証・固定の下で**再利用する。
既存の一般履歴の読取・HTML生成関数をそのまま使って保存許可や親の検証を省略しない。
リンク・ハードリンク・FIFO・ソケット・デバイス・ジャンクション／再解析ポイント・未取得属性は、読取／書込／削除の各入口で拒否する。
ファイルがない状態の判定と、権限拒否・破損・未対応を区別する。
保存先より上のフォルダーがない場合、一覧・整理・生成は保存先なしとして扱い、保存は作成せずに
`save_failed` と固定理由 `store_parent_missing`（パスを含まない）を返す。
上の要件は保存先が管理するファイル（記録・管理HTML／JSON・ロック・一時ファイル）に適用する。
所有者が置いた別のファイル（Finderの `.DS_Store` 等）は読取・追跡・削除せず、容量にも数えず、件数だけを一覧に示す。
その存在で保存・生成を止めない。公開・削除の後は保存先フォルダーもfsyncし、その失敗で保存済みを未保存と報告しない。

同一プロセス内と別プロセス間で専用ストアロックを使い、ロック待ちは最大1秒。
収集中には保存ロックを取らず、既存のプロセス確認ロックと入れ子で待たない。
収集済みの許可リスト化したスナップショットを受け渡し、保存・削除・期限整理・HTML生成の処理を直列化する。
親をdescriptor／検証済みハンドルで固定し、保存先とロックを毎回再確認する。
一時ファイルを同じ保存先に排他的に作り、サイズ確認・flush・必要な同期後に原子的に公開する。
一時ファイルも容量へ計上し、失敗時は自分が作ったものだけを回収する。
異常終了で残った一時ファイルは一覧ではデータとして扱わず、管理CLIで所有者・形式を確認して清掃する。

保存処理（ロック待ち・期限整理・HTMLの無効化・書込・同期・公開）は、収集の `timeout_seconds` とは別に
最大5秒の期限を持ち、各段階の間で期限と取消を確認する。公開前に期限切れになれば一時ファイルを破棄して
`save_failed`、公開が終わっていれば `details_saved` とする。収集結果の状態はどちらでも変えない。
ファイルシステム呼出しそのもののブロックは、現行の収集と同じく中断を保証せず、その制約を表示する。

## 上限・期限・削除

1 JSONは最大2MiB、対象数は現行の16件、各直接依存は100件まで。文字列・深さ・日時・列挙値も読み込み時に検証する。
HTMLは最大8MiB。レコード数・JSON・HTML・管理ファイル・生成一時ファイルの合計が設定上限を超える操作は拒否する。
単にJSONを解析できたという理由で任意のオブジェクトをHTMLへ流さない。
上限到達時は期限前の記録を自動で追い出さず、所有者にローカル一覧・選択削除を案内する。

期限は `saved_at + retention_days` とし、**現在時刻が期限以上（ちょうどを含む）で期限切れ**。
保存UTCは厳格に正規化し、未来の時刻・不正な日時は正常な記録として表示しない。
保持期間の変更では `min(記録済みの期限, saved_at + 現在の保持期間)` を有効期限とする。
短縮は既存分にも適用し、延長・再表示・再生成で既存分の期限を延ばさない。
時計の巻き戻り・不正日時を検出した場合は期限処理の制約を表示し、時刻だけから新しい証拠とは判断しない。

期限切れは保存・HTML生成の前に管理対象だけを整理し、通常の詳細読取・表示から除く。
保存許可は、この保持規則による期限切れJSONと管理HTMLの清掃許可を含むことをヘルプに明記する。
常駐処理・予約処理は追加しないため、操作しない間のディスク上の自動消去は保証しない。
実削除が必要なときは所有者が `prune --expired` を実行する。期限による非表示と実削除の件数を別々に示す。

削除は、ストア内の厳格なIDで特定したJSONだけを対象にする。内容に書かれたパスは削除先に使わない。
`revision` は読取済みレコードのバイト列に対する改変検出値とし、削除ロックの下で所有者・ファイル同一性・revisionを再検証する。
古い一覧指定、競合、他者所有、リンク等は削除せず一覧し直すよう案内する。
生成HTMLは内容の複製である。保持期間は所有者が設定ファイルを直接編集して変えるため、変更の前にツールが割り込むことはできない。
そこで、生成時に `dashboard.html` が含む保存IDと、表示範囲で最も早い有効期限を管理ファイル（0600）に記録する。
保存・一覧・生成・削除・期限整理のすべての管理操作は、最初にこれを現在の記録・保持設定と照合する。
表示中の記録が期限切れ・削除済みになっているか、現在の保持期間で有効期限が短くなっていれば、
他の処理より先にHTMLを安全に無効化（削除）する。保存・削除・期限整理で内容が変わるときも、変更の前に無効化する。
無効化できなければその操作を中止し、JSON削除だけで詳細が消えたと主張しない。
一覧での無効化も、保存許可に含まれる保持規則による清掃として扱う。
途中失敗した一括期限整理は、削除済み・未削除・失敗件数を返し、完了とは表示しない。
元のスクリプト、依存パッケージ、起動設定、一般履歴、チェックポイント、共用ロックは削除しない。

ブラウザーで既に開いたDOM・キャッシュ、所有者が作った別コピー、バックアップ、同期済みコピーは回収できない。
HTMLに生成時刻と表示範囲で最も早い期限、再生成が必要なことを静的に表示する。
静的HTMLが期限に自動で消えるとは説明しない。管理CLIの削除も安全な上書き消去を保証するものではない。

## ダッシュボードと未確認事項

専用のローカル静的HTMLをストア内の固定名 `dashboard.html` に生成する。
外部サーバー・外部画像・JavaScript・自動照会は追加せず、既存のCSPとハッシュ付きCSS、HTMLエスケープ、
制御／不可視文字の可視化を再利用する。名前・パス・ラベル・パッケージ名も指示として扱わない。
プロセスのパス、接続先、アプリ起動、外部サービスへのリンクは作らず、リンクは検証済みIDによるページ内移動だけ。
削除ボタン・設定変更ボタンは置かず、削除はローカルCLIへ限定する。

画面上部に、実情報を含むページであること、生成日時と収集日時の違い、期限、未確認は安全を意味しないことを表示する。
最新実行を先頭に置き、詳細は実行→対象の順に開閉する。過去の各実行は独立して表示する。
P01等は実行内ラベルであり、別実行のP01を同一プロセスとして集約しない。
対象実体を識別できた件数と、未観測・照合不可・未対応・取得不可の件数を分ける。
観測件数を脆弱性件数・重大度円グラフへ加算しない。
同じ保存IDの再読・HTML再生成では件数を増やさず、ページ生成時刻で古い確認を新しく見せない。
最新が `partial` / 空 / 破損の場合、過去の正常結果を最新として代用しない。
破損の可能性がある記録を飛ばした場合は件数と「最新を確定できない」を表示する。
ゼロ件・期限切れ・詳細削除済み・取得不可をそれぞれ異なる状態として示す。

| 状態・根拠 | 表示する説明 |
|---|---|
| `start_time_matches` | 前後の開始時刻が一致。秒精度・非原子的取得の限界あり |
| `not_rechecked` / 終了・不一致 | 実体未確認。確定済みの起動元や詳細として表示しない |
| `loaded_job_pid_matches` | 指定plist・プログラム・指定スクリプト・PIDをロード済みジョブと照合した範囲 |
| 設定一致だけ・取得不可・未対応 | 起動元未確定。RunAtLoad等の設定だけで現在の起動元を断定しない |
| `owner_selected_file_hashed` | 所有者が関連を指定したファイルのハッシュ。実ロードの証明ではない |
| 依存メタデータ発見 | 標準祖先配置で発見。実際の解決・実行・安全性は未確認 |
| 依存未発見・リンク・読取不可 | 理由を分けて未確認。未使用・悪性と推測しない |
| 署名・OSV・外部通信の用途 | この機能では未評価と明示 |

## 実装順序と受入条件

1. 設定検証、保存用の許可リスト、ストア所有者・親の固定・ロック・上限・重複防止を実装する。
2. CLIの二重許可による保存、匿名の保存状態、一覧・選択削除・期限整理を追加する。
3. 管理HTMLの無効化と専用ダッシュボードを追加し、汎用履歴からの自動読込がないことを確認する。
4. 合成データで回帰・Android/MCPを含む全テスト・npm通し試験を実行し、実ブラウザーと各OSの受入を別に記録する。

必須の回帰項目：

- 設定だけ・引数だけ・表示許可だけでは保存しない。無効・未作成のストアを勝手に作らない。
- 試験は一時フォルダーの `directory` だけを使い、既定の保存先の解決で失敗する。`save_failed` の警告がなく、既定の保存先が作られていない。
- 保存設定を有効にした実MCP呼出しでも保存がなく、応答・進捗・エラーに実名・PID・パス・保存ID等が出ない。
- 広い権限・他者所有・親／最終要素のリンク・ハードリンク・特殊ファイル・クラウド未取得・Windows再解析を拒否する。
- 前後照合が不確定な詳細を保存せず、取消・期限切れ後に背景保存しない。公開直前／直後の取消で保存状態が正しい。
- 期限の1マイクロ秒前・ちょうど・1マイクロ秒超過、保持短縮・延長、未来／不正日時を検証する。
- 保存・生成・削除・期限整理の別プロセス競合、ロック解放、revision不一致、途中失敗、一時ファイル回収を確認する。
- 保存処理の期限切れが公開前なら `save_failed`・一時ファイルなし、公開後なら `details_saved` で、収集結果の状態は変わらない。
- HTMLを削除・無効化できないとき、JSONだけを消して成功としない。管理対象外のファイルは触らない。
- 設定ファイルで保持期間を短くした後や、表示中の記録が期限切れになった後は、どの管理操作でも最初にHTMLを無効化する。
- 同じ実行IDの記録が2件ある場合に二重計上せず、最新の確定結果として表示しない。保存の自動再試行がない。
- 記録数・全体／JSON／HTML上限、同じID再読、最新がpartial・空・破損・期限切れ、旧スキーマを確認する。
- ソース・生出力・引数・環境変数・接続先を保存せず、HTMLの注入・パス／外部リンク化・外部通信がない。
- ブラウザーで詳細開閉・ページ内移動・件数・未確認表示を確認し、表示済みコピーの削除限界も説明どおりか確かめる。

実機受入は別途許可された対象だけを使い、実名・パス・スクリプトのハッシュ・画面画像はローカルだけに保持する。
リポジトリには合成フィクスチャ、成否・件数・対象コードのハッシュ、未確認事項だけを残す。
